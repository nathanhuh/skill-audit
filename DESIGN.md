# Design: inventory, acquire references, audit

Binding decisions are in the [architecture decision records](docs/adr/README.md). This document describes the architecture as built, and where it disagrees with an ADR, the ADR wins. The ADR gap tables list where the code does not yet follow its ADR. [CONTEXT.md](CONTEXT.md) defines the vocabulary. Dated review plans that led to the current design are kept in [docs/history/design-review-notes.md](docs/history/design-review-notes.md); they are history, not policy.

## Architecture
The sole CLI is `cmd/skill-audit`, using the inventory/search/sync/audit workflow. The canonical document-driven implementation keeps the workflow in one `internal/audit` package: `inventory.go` owns discovery, `content.go` measurement, `catalog.go` matching, `observe.go` orchestration/comparison, `storage.go` persistence, `wire.go` report/catalog compatibility, `search.go` search provenance/compatibility, `acquire.go` explicit network acquisition and `scanner.go` the optional adapter. Filesystem and child-process differences stay in `fs_*` and `process_*`. The frozen implementation is compared in [docs/rewrite-comparison.md](docs/rewrite-comparison.md). Local evidence collection is separate from explicit network acquisition.

1. `inventory --device --out inventory.json` walks accessible filesystem roots for every SKILL.md package. On Unix device defaults to `/`; on Windows it enumerates existing drive roots. Repeated `--root` narrows/extends explicit searches. Deterministic traversal prioritizes home/user/agent paths with lexical tie-breaking and excludes virtual OS trees, symlinks, Git metadata and common dependency/build caches, with explicit diagnostics. Permission errors, deadlines, entry/depth/package limits and exclusions prevent universal completeness claims. Nested package manifests are found too. Scope/path and agent hints are observations, not activation proof.
2. `search --query 'web artifacts'` sends only the explicit query to GitHub's authenticated code search, with `filename:SKILL.md` added. No local content is transmitted. An explicit --inventory plus --search-names option sends deduplicated recorded names, capped at ten queries. Search coverage is bounded and results are only leads, not correlations.
3. `sync --repo owner/repo --ref HEAD --out catalog.json` checks that a repo is public, resolves the ref to an immutable commit, reads its Git tree and blobs, and imports bounded complete SKILL.md packages into a versioned local catalog. Git symlinks/submodules or truncated/oversized trees/packages are rejected, not counted as exact. Root licenses/notices are retained as attribution separately from package bytes. Search/sync are the only network commands. Local cache is not automatic redistribution permission.
4. `audit --inventory inventory.json [--catalog catalog.json]` re-reads inventory paths, detects content drift, correlates against the built-in pinned catalog or an explicit override and runs local scanning. Optional `--xray` keeps upstream scanner isolation. Optional `--state --record baseline|snapshot` reuses immutable-baseline lineage. Audit is offline except an explicitly supplied trusted external executable's own behavior; our adapter never enables its network/LLM modes.

The explicit acquisition step is more reviewable than an implicit internet search during every scan: local private data never becomes a query without the operator choosing it; results can be reproduced offline against saved commits. A user may search by a skill name, but full content comparison still decides whether it correlates. A renamed skill might need a different user query. GitHub index limits, auth/rate limits and incomplete results remain visible.

API contract: GitHub REST 2022-11-28, `application/vnd.github+json`, GET /search/code, /repos/{owner}/{repo}, /repos/{owner}/{repo}/commits/{ref}, /repos/{owner}/{repo}/git/trees/{tree}?recursive=1, /repos/{owner}/{repo}/git/blobs/{sha}. No shell, git clone, arbitrary download URL, scripts or redirects. Requests have timeout, response/file/total byte bounds, and a request budget. GitHub repository grouping is case-insensitive; ref and package-path spelling stay case-sensitive. Credentials come only from GH_TOKEN/GITHUB_TOKEN and are never serialized. Default tests use fake HTTP transports and fixtures. No provider/plugin framework.

Catalog storage contains actual bytes (base64 JSON), hashes, repo/commit/path and retained attribution. Optional external runtime catalogs remain outside scanned packages and can be copied to an offline VM. The pinned two-skill catalog is the default for offline audit, tests and the demo. State is JSON rather than a database. Desktop Windows remains compile-only until native path, state replacement and process cleanup testing; see PORTABILITY.md.

Configurable registry acquisition supports the documented Skills.sh v1 search response using --registry-url and a separate SKILL_AUDIT_REGISTRY_TOKEN. GitHub remains the default. Saved search output is consumable by sync; GitHub package paths or registry directory-slug hints select the package before full content comparison. This is not arbitrary-registry compatibility or registry-backed proof of origin.

## Inventory and fingerprints
Local identity is `(scope, absolute lexical package path)`, independent of declared name. Priority traversal with lexical tie-breaking and sorted root/package report arrays. Skip all symlinks (including path components), special files, and excluded `.git`, `.hg`, `.svn`, `.DS_Store` metadata. Report every skip; only intentional metadata exclusions leave the content fingerprint complete. Bound each file to 1 MiB, each package to 16 MiB and 1,000 entries. Without scope flags, inventory defaults to the same device roots as `--device`; explicit `--root` alone stays narrow. Tests inject device roots rather than scanning the host. `inventory --state PATH` designates one state file for an explicit, reported discovery exclusion; directories and locations inside packages are rejected. Unavailable selected roots and I/O/metadata errors become diagnostics and exit 2 while independent packages continue.

YAML frontmatter is parsed as data with a pinned YAML parser. Optional string name defaults to directory name; description/name type errors, duplicate fields, invalid YAML, and unterminated frontmatter are diagnostics. This is not a full Claude schema validator.

Local manifest names use one host-local UTF-8 slash-relative path rule for measurement, state reading and staging (ADR-0009 P5). Colon and literal backslash are valid Unix names; traversal and unsafe native forms are refused. Remote acquisition/catalog paths retain their separate portable boundary.

Hash raw bytes with SHA-256. Directory digest v1 hashes a domain separator followed by sorted records: uint64 big-endian path byte length, UTF-8 slash-relative path bytes, and the 32-byte file hash. No timestamps, permissions, empty directories, state files, or excluded metadata. Incomplete packages have observed file hashes but no authoritative directory digest and cannot be exact matches.

## Catalog fixtures and matching
Retain two complete Apache-2.0 fixture packages, brand-guidelines and web-artifacts-builder, from anthropics/skills at dbd4588f9e1033efb41dad4bef2f7947c8993d44. Preserve licenses and third-party notices outside package comparison metadata. These pinned packages support offline audit, tests and the demo; audit uses these by default or an external catalog selected by the operator. Manifest records repository, commit, upstream path, per-file hashes, and directory digest; verify embedded files against it on load. Catalog evaluation identity hashes sorted reference metadata and per-file fingerprints with the skill-audit/reference-catalog/v1 domain marker; it excludes separate acquisition diagnostics and attribution packaging.

Exact means complete directory digest equality. Modified candidates use one method: Jaccard similarity of sets of nonblank trimmed content lines (minimum length 20 bytes), keyed by relative file path, excluding SKILL.md frontmatter and license/notice files. Only UTF-8 text without NUL bytes contributes. Threshold 0.60 with at least three shared lines. Names never contribute. Every qualifying candidate is retained; multiple exact or modified candidates are ambiguous, not arbitrarily ranked into certainty. Report shared/union counts and score. This detects small edits and bundled changes but misses major rewrites, cannot infer authorship, and can confuse shared templates. A match is content evidence, not proof of who copied it.

## Lineage
Accepted storage policy ([ADR-0004](docs/adr/0004-observations-and-baselines.md), implementation of the designated discovery exclusion still to be verified): versioned JSON manifest outside every skill package, in a designated state location explicitly excluded from discovery with reported exclusion evidence: immutable baseline plus append-only observations, UTC observation time, catalog identity, local identity, snapshot digest and hashes, scanner evaluations and findings, and upstream reference with basis (`observed_exact_match` or `inferred_candidate`; the state reader also accepts previously recorded `user_declared_origin`). Unknown or ambiguous origin stays unresolved. Each observation stores its own correlation; later observations do not rewrite baseline origin.

Added/removed/modified paths compare current complete inventory with the baseline, separately from upstream correlation. Missing tracked packages are reported as missing, not silently deleted. Incomplete inventories produce an unavailable comparison rather than false removals. A changed catalog disables upstream historical comparison and is reported; local baseline comparison remains possible. Corrupt/unsupported state is a hard diagnostic, never reset. A lock file prevents concurrent writes; exclusive baseline creation and same-directory temp/file-fsync/rename protect writes. Directory fsync is attempted on Unix; Windows skips that unsupported operation and has weaker, unverified replacement durability. Preserve previous observations; cap state reads at 32 MiB. Stale locks require manual inspection/removal. No Git requirement, rename tracking, content recovery, author attribution, prior history, or tamper-proof claims.

Only label a finding `new` when the same scanner/rule evaluation version completed on both observations and it was absent from baseline. Otherwise label it `present_in_changed_file` when applicable. External scanner findings never get `new` in this MVP because its version string alone does not pin every ruleset/configuration input.

## Scanner boundary
Own rule SA001 v3: parse .sh/.bash files with the pinned mvdan shell parser; find adjacent pipeline stages from a literal curl/wget HTTP(S) request on stdout into literal sh/bash, including within longer pipelines. Redirections must preserve the relevant pipe descriptors; shell option termination is interpreted in order. Recognize the ADR-0012 receiver subset (`-e`, `-u`, `-x`, `-v`, `-s`, including grouping); wget must request stdout. AST parsing avoids treating comments, quoted examples, or heredoc text as commands. No execution, URL fetching, expansion evaluation, alias/function resolution, general dataflow, descriptor moves/variable descriptors, direct |& analysis, or Markdown fence analysis. Unsupported shell files and syntax errors are coverage notes/gaps. Non-shell files are hashed but outside this rule's analysis scope. Report source, rule/version, high severity, relative file, line, bounded evidence, rationale and limitations. A risky pattern is not malicious intent.

Skill X-Ray is a separate optional scanner, not original detection logic. Interface pinned to traceforce/skill-xray commit c89eacfdd643e50d5f8e3ed18cf3c4992d174ff2, version 0.1.0: `version`, then `scan --output REPORT --llm=false -- ABSOLUTE_LOCAL_PACKAGE`. SARIF 2.1.0 only. Preserve original results/run properties, severity, rule ID, tool version, evidence and locations. Check `properties.coverage`; zero exit alone cannot imply completion. Statuses: disabled, unavailable, failed, partial, completed_with_findings, completed_without_findings. Local results survive adapter failures. `--scan-timeout` defaults to 30 s for the probe and each scan. Each phase leaves a best-effort reserve of 25% of `--timeout`; probe/launch failure, scan timeout or reserve skip stops later scanner launches. Only probe exit 75 gets one retry, sharing the original phase deadline (ADR-0006).

Use direct exec argument arrays, context timeout/cancellation, bounded stdout/stderr and report read, isolated temporary report directory outside packages, version refusal, and no URL targets. Run on a staged copy of the exact inventoried bytes to exclude symlinks and changes during scanner execution; incomplete inventory forces partial status. No installation or network/LLM flags. User-supplied executables are trusted code; this is not a process sandbox. OpenGrep 1.29.0 is separately required by upstream for code coverage. Missing engine must remain a gap. Real execution only if the tool is already available and safe; otherwise source-verified and fake-tested, runtime unverified.

## Output, dependencies, and acceptance
Report/v2, inventory/v3 and state/v3 have separate version markers. Readable escaped terminal strings and deterministic JSON ordering (observation timestamps intentionally vary for explicit snapshots). Priority: security findings 1, then failed pre-commit recording 3, then incomplete/operational or durability uncertainty 2, otherwise 0. Recording is independent structured output; requested recording is printed once on stderr, and once on text stdout, while ordinary audit prints no recording line. Disabled optional scanning is not a gap. Published state/v1 remains comparison-readable and append-read-only; unpublished state/v2 is rejected. No state is migrated.

Use standard libraries except pinned `gopkg.in/yaml.v3 v3.0.1` for correct frontmatter and `mvdan.cc/sh/v3 v3.10.0` for shell syntax. Vendor dependencies for offline builds/tests. Avoid concurrency, database, service, UI, generic plugins, and fuzzy/LLM matching.

Acceptance tests: duplicate names across scopes; unavailable explicit roots; symlink and size skips; malformed YAML; bundled-byte changes; exact/modified/ambiguous/unknown and misleading names; baseline immutability and append persistence; additions/deletions/missing directory/corrupt state/catalog change; detector positives and comments/strings/heredocs/non-executed downloads; fake scanner timeout/bad JSON/no report/partial coverage/version errors; local findings retained after external failure. A temporary demo copies the catalog, records baseline, modifies a bundled shell script with download-to-shell, and shows modification plus a comparable new finding. Finish with gofmt, vet, offline tests, build and CLI smoke checks.

## Accepted review amendments (2026-10-29)

ADR-0010 bounds inventory gap details (1 MiB/1,000 records) and total formatted output (64 MiB) while preserving whole measurements and explicit omissions/stopping location. Mandatory scope/coverage-envelope failure is explicit. ADR-0011 uses exact lexical paths or confirmed filesystem identity for role collisions; it permits distinct case-only files and revalidates before every write. Report discovery metadata carries truncation counts through audit/state.

Runtime interruption is an internal operation fact, never inferred from imported diagnostic codes. In-scope state paths not declared by the saved inventory are visible coverage gaps and cannot be recorded without refreshed exclusion evidence. Rejected roots do not participate in delegation. Scanner staging validates the temp base against every audited package before any write. Log overflow retains its own cause and actual exit code, and does not stop later package scans. Sync serialization admission counts only newly added values at their actual formatted depth; final serialization remains the write-bound backstop.

## Second review decisions and corrections

ADR-0003 D13 puts explicit roots before device-added roots. Per-group root ordering and no-follow delegation remain unchanged. New reference imports omit declared metadata path components to match local directory/v1 collection; stored catalogs are not migrated, and dependency omissions still make local measurements incomplete. Per-package staging failures do not become terminal session failures. Final inventory output refusal marks coverage incomplete and is checked before stdout delivery as well as file output. Report readers preserve per-skill incomplete diagnostics. A single sync-budget finalizer also covers the final search-diagnostic budget path. SA001 v3/evaluation is an explicit behavior-version bump under ADR-0012 and ADR-0008; v2 finding transitions are not comparable.

## Third review corrections and accepted search decision

Validated SARIF coverage decides scanner completion after an ordinary process exit; non-zero exit evidence remains visible. At the scanner pin, complete scans including security findings exit 0, while errors/incomplete high-severity analysis exit 2. Delegated discovery aliases name their separately selected root without pretending that unknown linked content was inspected. Report JSON exposes overall complete and created_at alongside independent discovery coverage. State hash spelling is normalized only in memory; original observations stay unchanged. Field-tuple sorts retain deterministic ties, and admitted attribution is reused outside the blob cache.

ADR-0012 R4 adds lone-dash option termination for receivers; a later filename still needs -s. Unpublished SA001 v3 is retained. Accepted ADR-0013 changes search output to v3 with flat input batches preserving source, query list, hit membership, completeness and diagnostics. Both search and sync accept saved plus live inputs. Published v2 remains readable as one opaque-query batch; files are not migrated. Sync still deduplicates imports and retains its API, commit and budget contracts. See docs/review-3-fixes.md and VERIFICATION.md.

## Fourth review evidence corrections

Scanner messages append process/measurement causes to SARIF coverage, including non-zero exits; they never replace that coverage cause or add empty separators. Duplicate selected roots retain delegation evidence. Inventory/catalog/state readers canonicalize valid SHA-256 spelling in memory; content hashes and fingerprint encodings are unchanged. Acquisition targets and identical full diagnostic causes deduplicate independently of provenance membership, without disabling retries on later distinct targets.

The accepted ADR-0013 Q4 amendment records one batch per newly requested query, with the selected provider established before validation and query-specific hits/errors. Older grouped v3 and opaque-query v2 evidence stay intact. Inputs are the only mutable search evidence; views are computed and serialization does not re-sort. New state observations use observed_at alone; report created_at is for delivery. Matching historical duplicate times remain readable, conflicting times are invalid, and original historical fields remain preserved. See docs/review-4-fixes.md and the pre-publication checklist in VERIFICATION.md.
